TANSHIN PIPELINE WORKING RULES

1. Never manually edit a generated or exemplar Markdown report.
   Report changes must be made in the generic pipeline, prompts, schemas,
   normalization, validation, or rendering code and then produced by a normal
   pipeline run or offline reprocessing.
   This restriction does not apply to source documentation such as README.md
   or AGENTS.md when documentation itself is being maintained.

2. Preserve historical runs. Do not improve a report by patching its rendered
   output or by overwriting historical artifacts outside the pipeline's normal
   archival process.

   The default report root is final_output/. Canonical Markdown filenames end
   in the local run date as YYYYMMDD. When reports are archived under a
   timestamped history directory, preserve those dated filenames unchanged.

3. Judge report quality primarily through direct qualitative review against the
   exemplars and prior runs. Deterministic comparison scores are diagnostic
   metadata only and must not be treated as the authoritative quality judgment.

4. Keep all changes company-agnostic. Do not add company-specific report fixes.

5. Never initiate a Gemini or OpenAI API request from automated development
   work. Every API-backed run must be started manually by the user.

6. English narrative prose renders yen-denominated statement amounts at or above
   ¥1 billion in one-decimal billion notation, smaller amounts in million
   notation, and per-share amounts as forms such as ¥95 per share. Preserve
   economic value within display precision, scale, sign, percentages, margins,
   payout ratios, and statement type; never perform foreign-exchange conversion.
   Reader-facing reports do not render inline citations or evidence ledgers.
   Lightweight source provenance remains in structured diagnostic artifacts.

7. Keep model names as source constants in tanshin_pipeline/config.py. The .env
   file is credentials-only and may contain GEMINI_API_KEY, GEMINI_API_KEY2,
   and OPENAI_API_KEY.

8. A Japanese report uses a PDF-backed research request and a separate
    dossier-backed synthesis request. Optional English translation is a third
    request. The default profile uses gemini-3.6-flash with GEMINI_API_KEY for
    every stage. The key2-translation profile changes only the translation
    credential to GEMINI_API_KEY2. When consecutive stages share a Gemini
    credential, preserve a 75-second inter-stage cooldown whenever their
    combined estimated input and maximum-output allowance reaches 225,000
    tokens, leaving 10% headroom below the 250,000-token planning limit.
    Research is coverage-first: every selected filing receives an explicit
    coverage record, while Python derives forecast, target, and
    commentary-change metrics before the synthesis request. Request 1 extracts
    filing-specific information and does not rank business drivers, decide
    longitudinal themes, score management, or draft final conclusions.
    Keep the research dossier bounded and reuse lightweight source records;
    requested counts are ceilings rather than quotas.
    Within that bounded dossier, require explicit per-filing coverage of
    operating results, financial condition, forward-looking information,
    strategy and plan progress, segment conditions, capital allocation, and
    material footnotes. Compress comparable annual forecast-result pairs into
    one financial anchor per year-end filing so qualitative management
    discussion, recurring commentary tracks, and commitments with later
    outcomes take priority over broad historical table duplication,
    miscellaneous boilerplate, or routine footnotes.

9. For a default, primary-key-only run, explain that generation should be free
    when GEMINI_API_KEY is eligible for Gemini's free tier. Any displayed yen
    amount is a conservative paid-tier upper-bound estimate.

10. Deterministic validation is intentionally non-gating. Run it and preserve
    all diagnostic artifacts, but do not let valid, publishable, error, warning,
    or quality-score results suppress canonical Markdown for a response that
    can be parsed, normalized, and rendered. Manual review is the publication
    authority. API, structured-output parsing, missing-artifact, processing, and
    rendering failures may still stop the pipeline.
    Research-dossier cross-checks follow the same policy: a Pydantic-parseable
    dossier proceeds to synthesis while findings remain diagnostic artifacts.
